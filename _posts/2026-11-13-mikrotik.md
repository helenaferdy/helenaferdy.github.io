MikroTik RouterOS can combine routing, VLAN-aware switching, NAT, and stateful firewalling on one device. In this lab, it provides management and WAN connectivity, routes the Core, Server, and DMZ VLANs, and applies different Internet and inbound-access policies to each zone.

## Initial Config

The initial CLI configuration gives `ether1` a management address, creates the route to the management network, enables SSH, and sets the local administrator password.

```
/ip address
add address=198.18.129.61/18 interface=ether1 comment="Mgmt"

/ip route
add dst-address=10.16.35.0/24 gateway=198.18.128.1

/ip service enable ssh

/user set admin password=P@ssw0rd
```

![Initial CLI configuration](/static/2026-11-13-mikrotik/01.png)

<br>

The topology separates the design into three layers. `bridge1` is the VLAN-aware Layer 2 domain, while VLAN interfaces on the bridge are the Layer 3 default gateways. The Core uplink uses an `802.3ad` bond on `ether3` and `ether4`; `ether5` carries the Server VLANs as a trunk, and `ether6` is an access port for the DMZ.

![Bridge architecture and topology](/static/2026-11-13-mikrotik/01a.png)

<br>

Descriptive interface names make the physical role of each port immediately clear: management, WAN, Core, Servers, and DMZ.

![Adding the DMZ port](/static/2026-11-13-mikrotik/42.png)

<br>

![Configuring the DMZ access port](/static/2026-11-13-mikrotik/43.png)

<br>

The port list confirms `ether6` uses PVID 31.

![DMZ bridge port](/static/2026-11-13-mikrotik/44.png)

<br>

![Dynamic VLAN 31 entry](/static/2026-11-13-mikrotik/45.png)

![Setting masquerade](/static/2026-11-13-mikrotik/54.png)

## Firewall

The final filter rules use default-deny behavior. The input chain allows management from `ether1` and ICMP before dropping other traffic directed at the router. The forward chain permits established or related flows, DNAT connections, Core Internet access through `ether2`, and internal `192.168.0.0/16` routing; the final drop blocks everything else. This prevents the DMZ from initiating unrestricted access while still allowing the published web service to receive its forwarded connection.
